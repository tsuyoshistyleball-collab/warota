# 📡 わろたんてな

世界の話題ニュースと、5ちゃんねるまとめサイトの新着記事を集める**自分用ニュースアプリ**。

- 🌏 **ワールド** — 世界地図から地域を選ぶと、いま話題のニュースTOP10。見出しをタップすると最初に要約を表示
- 📰 **まとめ** — まとめサイトの新着を1画面に集めるアンテナ([ワロタあんてな](https://matomeantena.com/) 風)
- 📱 **スマホ最適化 + PWA** — ホーム画面に追加すればアプリとして使える。Galaxy Z Fold などの折りたたみスマホは、開くと上に大きな地図、その下に左右2画面
- 🚫 **広告なし** — このアプリ自体には広告が一切ない(記事タップで開く元サイト側の広告は元サイト次第)
- 💰 **完全無料・サーバー不要** — GitHub Actions が30分ごとに RSS を取得し、GitHub Pages で配信
- ⚙ **設定** — 地図の大きさ、NGワード、表示するサイト、既読の管理をまとめて変更
- プルリフレッシュ / タイトル検索 / お気に入り / 既読管理

## セットアップ

基本的に**自動**です。デフォルトブランチにワークフローが push されると、GitHub Pages の有効化・記事取得・デプロイまで自動で行われ、以後30分ごとに更新されます。

- 公開URL: `https://<ユーザー名>.github.io/warota/`
- 手動で今すぐ更新したいとき: **Actions タブ → 「All workflows」→ `update` → 「Run workflow」**

> ⏰ 定期実行(スケジュール)は**デフォルトブランチ上のワークフロー**だけが対象です。
> また、リポジトリに60日間pushがないとGitHubがスケジュール実行を自動停止します。これを防ぐため、最後のコミットから50日経つとワークフローが空コミットを自動で積みます。
> それでも止まった場合は **Actions タブ → `update` → 「Enable workflow」** で再有効化してください。

## スマホのホーム画面に追加(アプリ化)

- **iPhone (Safari)**: ページを開く → 共有ボタン → **「ホーム画面に追加」**
- **Android (Chrome)**: ページを開く → メニュー(⋮) → **「ホーム画面に追加」** または「アプリをインストール」

## 使い方

画面下のタブ、または画面を左右にスワイプして **ワールド** / **まとめ** / **設定** を切り替えます。

### ワールド

| 操作 | 機能 |
|---|---|
| 地図の地域・地域カードをタップ | その地域の話題のニュースTOP10 |
| 地図の下の「地図 小・大」 | 地図の大きさの切り替え(設定からも変えられます) |
| 地図を指でドラッグ | 地図を動かす(「小」のときは、2本指で拡大してから。拡大していないときはページがスクロールします) |
| 2本指で広げる・縮める / ＋−ボタン | 地図の拡大・縮小(「世界全体」ボタンで元に戻る) |
| 見出しをタップ | 要約 → 元記事へのリンク → 同じニュースを伝えた他のメディア の順に表示 |
| 地図の色 | 話題の盛り上がり(薄い=落ち着き、濃いオレンジ=話題沸騰) |
| ↻ / 下に引っ張る | 手動更新(5分ごとに自動更新もされます) |

話題の順位は「同じ出来事を何社が報じたか」「Yahoo!トピックスやアクセスランキングに入ったか」「新しさ」から計算します。
要約は各報道機関が配信している記事の概要(RSS・ページの説明文)です。

### まとめ

| 操作 | 機能 |
|---|---|
| 記事をタップ | 元サイトを新しいタブで開く(開いた記事はグレー表示) |
| 上部のタブ | カテゴリで絞り込み(総合 / ニュース / VIP / ゲーム…) |
| 🔍 | タイトル検索 |
| ↻ / 下に引っ張る | 手動更新(5分ごとに自動更新もされます) |

### 設定

| 項目 | 内容 |
|---|---|
| 地図の大きさ | 小: 世界全体を小さく表示し、記事を広く見られる / 大: 画面上部に大きく表示し、指で動かせる |
| 記事をアプリ内で開く | まとめの記事を広告を省いて表示する |
| 既読の記事を隠す / NGワード / 表示するサイト | まとめの一覧の絞り込み |
| 既読履歴をリセット | まとめの既読の印を消す |

変更はすぐに反映され、次にアプリを開いたときも覚えています。

## 収集サイトのカスタマイズ

[`feeds.json`](feeds.json) を編集して push するだけです。

```json
{ "name": "サイト名", "url": "https://example.com/index.rdf", "category": "総合" }
```

- livedoor系まとめブログの RSS は大抵 `https://ブログのURL/index.rdf`
- カテゴリは自由文字列。同じ文字列同士が1つのタブにまとまります
- 取得に失敗したサイトは自動でスキップされます(Actions のログで確認可能)

ワールドのニュース元は [`world-feeds.json`](world-feeds.json) です。

```json
{ "name": "NHK 国際", "url": "https://...", "kind": "world", "role": "content", "outlet": "NHK" }
```

- `kind`: `world`(海外のニュース)/ `mixed`(国内外が混在)/ `japan`(国内のニュース)
- `role`: `content`(要約・画像を使う記事)/ `signal`(話題度の判定だけに使う見出し)
- 地域の判定に使う国名・地名は [`scripts/world-regions.mjs`](scripts/world-regions.mjs) にあります

## 更新頻度を変える

[`.github/workflows/update.yml`](.github/workflows/update.yml) の `cron` を編集します(UTC表記)。
例: `*/20 * * * *` = 20分ごと。GitHub の仕様上、指定時刻より数分〜数十分遅れることがあります。

## ローカルでの開発

```sh
npm run fetch        # feeds.json から public/data.json を生成
npm run fetch:world  # world-feeds.json から public/world.json を生成
npm run serve        # http://localhost:3000 でプレビュー
npm test             # 地域の判定・話題のまとめ方・まとめ記事の本文の取り出し方のテスト
```

世界地図のデータ `public/world-map.json` は [Natural Earth](https://www.naturalearthdata.com/)(パブリックドメイン)から作っています。
地域の分け方や色を塗る範囲を変えたときは、次のコマンドで作り直します。

```sh
npm install --no-save --no-package-lock d3-geo topojson-client world-atlas
node scripts/build-map.mjs
```

アイコンの元画像は [`assets/icon-source.png`](assets/icon-source.png)。差し替える場合はここから
512 / 192 / 180px に縮小して `public/icon-512.png` / `icon-192.png` / `apple-touch-icon.png` を上書きします。

## 仕組み

```
GitHub Actions (30分ごと)
  ├─ scripts/fetch.mjs が feeds.json の各RSSを取得・整形 → public/data.json
  ├─ scripts/build-articles.mjs がまとめ記事の本文を取り出し、広告・宣伝・コメント欄を除く → public/articles/
  └─ scripts/fetch-world.mjs が world-feeds.json の各RSSを取得
       ├─ 見出しの国名・地名から地域を判定
       ├─ 同じ出来事を伝える記事を1つの話題にまとめ、話題度で順位付け
       └─ public/world.json (地域ごとのTOP10) → GitHub Pages にデプロイ
            └─ スマホの PWA (public/) が data.json / world.json を表示
```

依存パッケージゼロ(Node.js 標準機能のみ。記事の本文の取り出しだけは、ワークフローの中で linkedom と @mozilla/readability を入れて使います)。
まとめは直近7日分・最大1000件、ワールドは直近7日分の記事から話題を選びます。

### 記事の本文の取り出しを点検する

アプリ内で開いたまとめ記事に広告や関係のない文字が混ざるときは、GitHub の Actions から `debug` ワークフローを手動で実行して調べます。

| 入力 | 調べる内容 |
| --- | --- |
| `audit 0-9 2 brief` | 0〜9番目のサイトの最新2記事ずつ、本文の量と、残っていそうな宣伝の言葉の前後 |
| `audit 2,5 1 html` | 指定したサイトについて、取り出したHTMLの最初と最後まで |
| `snip 29.0 なんじぇい` | 29番目のサイトの最新記事で、その文字が元のページでどう書かれているか |

サイトの番号は `feeds.json` の並び順(0から)です。`base` にコミットやブランチを入れて `brief` で実行すると、その版と比べて消えた行・増えた行も出ます (抽出のしかたを変えたときに、本文まで消していないかの確認用)。
